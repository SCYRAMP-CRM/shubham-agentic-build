## Boundary

A partial is computation only. It must never enter the normal host, get an order origin, execute a tool, write conversation history, create a card, or make a sound. The separate preview process has no MCP servers, no native tools and no usable app tool key. Its user text is sent through stdin, never a prompt file. It has no durable history. Its lifetime, input, output and work are bounded; interruption, disconnection, takeover and tab changes invalidate it.

Only an owner web connection whose current start declares `page: quick`, `talk: true` and `ahead: true` can prepare. Chris, the bar and V1 cannot accidentally opt in. Every reconnect repeats the declaration. An older server lacks the preview capability, so the client sends it no preparation frames.

Silent remains step 2a's listening-without-speaking mode in both tabs. Entering it discards preparation; room speech never enters the preview model. Silent and pre-tap room pieces keep their existing recognition bound and one-at-a-time transport, rather than inheriting V2's six-second cuts. Speak restores preparation for new speech, not for room words already in flight. A lost room piece stays a placeholder, never a spoken retry. An `ahead` option alone cannot enable V2 outside the Quick page.

The final transcript is authoritative. A completed preparation is usable only for the exact same text, model and connection. A mismatch, unfinished preview, timeout, low memory or failure falls back immediately to ordinary Quick; final processing never waits for preparation. The draft is untrusted supporting text, not an instruction, an approval or evidence that something happened. The existing final host still decides what to say and what tools it needs. All Quick-page handoffs retain their tap-to-send rule.

If recognition loses any piece of a V2 utterance, the surviving prefix is NOT a final command. V2 discards the preparation and asks him to repeat instead of asking the tool-capable host with incomplete words. V1 keeps its original handling. Recognition can still mishear words; this is not voice identification or a guarantee of transcription accuracy.

This first version deliberately does not speak a speculative answer directly. Doing that safely also requires synchronizing the durable conversation and the warm normal process. Tool-free output alone cannot prove a request needs no action. Likewise, an answer started on a prefix is not automatically suitable for a final sentence containing a correction or negation.

## Timing and limits

V2 overlaps local recognition and bounded model preparation with speech. It uses the installed recognizer, existing model/account and voice. There are no downloads or new services. The extra process uses the existing memory gate, is disposable and may be unavailable when resources are low. Partial text is never treated as a finalized history entry.

The tabs show the last observed wait from the end of speech to first answer audio on this device. No synthetic benchmark is presented as live speed. Live before/after results remain unmeasured until a published build is used on the actual device. A second final model pass remains, so preparation alone is not a promise of faster first audio; the bounded transcription pipeline is the other change to compare.

Source composition preserves the usage subscription captured from the same credential read as each process's environment (order of130). Each preview captures its own subscription key; starting it cannot change the still-warm ordinary host's attribution. Only numerical cost totals use the existing usage ledger, never draft words. V2 adds inference work even when a draft is discarded.
The disposable process starts its usage counter at zero: the usage ledger otherwise treats its sole result as an existing baseline and would silently omit the entire preview cost. The ordinary host's established accounting path is unchanged.

Tests must prove partial-command isolation with a positive completed-command control, V1 parity, complete ordered transcription, corrected-text discard, stale result/cancel/reconnect fencing, no waiting for failed previews, and keyboard/tab switching. Phone audio, echo, actual recognition accuracy at piece boundaries and device latency need real use after publication.

## Independent review follow-up (server-only)

**F1: actual `.cmd` argument loss.** Agent 14's harmless argument-printer probe (no model/provider) demonstrated that a multiline inline preview brief truncates the Windows `.cmd` launch: only 2 of 17 arguments arrived and none of the 14 nonempty arguments after the brief. One-line and prompt-file controls preserved all 17. This is a latent sandbox fault on installations using `claude.cmd`, not the executable installation on this PC. The fixed brief is one line. More importantly, the shared host launch validates the executable and EVERY actual argument for CR/LF before creating its working/control files or appending `journal.process`. User speech remains on stdin. Invalid launch configuration now visibly refuses; valid normal-host arguments, permissions, accounting and conversation behavior must still match published V1.

This early validation is intentional malformed-config hardening on the normal/old-reader paths too. The supervisor catches `spec.start` exceptions and retains its existing retry/backoff behavior; a deterministic refusal must not append a process row and rewrite files on every retry. The guard itself was already contained by that supervisor catch, not by F4. The regression uses real harmless `.cmd` execution with the actual host argv, an intentionally multiline negative control that must really lose flags, raw-spawn counters independent of fake-hook assertions, and all-argv assertions in the existing host/app test hooks. No real provider is used.

**F4: V2 fault containment protects V1.** Every public preview method contains exceptions, drops speculative generations and disables further speculation on unexpected dependency failure. Provider callbacks and asynchronous opening/ticking are separate contained boundaries too. Uncertain process disposal never licenses another preview. The shared housekeeping callback performs normal voice, normal host, old reader and card expiry first; only the optional preview call has its own final catch. An earlier V2 exception must not skip V1 work. A whole-body catch with preview last would also be wrong: it would silently swallow an unrelated V1 fault. This does not claim to repair the app-wide pre-existing callback exception policy. The effect pin executes the production interval body with counting dependencies, throwing/nonthrowing preview controls, and a V1 fault that must remain visible rather than being swallowed.

An unexpected host construction/open/ask/tick rejection disables speculation until the coordinator is restarted. A transient rejection can therefore leave V2 doing six-second transcription but no model preparation for that app run. Normal memory admission returning a readable refusal is not an exception. This conservative V2 degradation is accepted and recorded, not described as a normal-host failure or a speed improvement.

**L1, required diagnostic:** every permanent-latch site, including thrown/rejected stop and uncertain process exit, routes through one once-only notifier. It passes exactly one closed-set method/location literal to optional `onFault`; no exception, argument, connection/id, transcript or draft is passed. The app logs one CONSTANT warning saying preparation is disabled and how to retry, with no dynamic fields. Repeated faults do not flood the log. The callback itself is contained if the logger throws. There is deliberately no UI/protocol change. The new pins assert one call across three faults, all disposal sites, secret sentinel exclusion, a throwing diagnostic at every public method, and the actual app factory's constant warning.

**S14-state-lifecycle coverage.** The existing `onState: undefined` override in the disposable host factory remains unchanged. Its new app-level effect pin starts, answers and disposes a real fake-provider preview while a V2 socket and a connected V1 bar observe state; neither may receive extra normal-host state frames. The preview-start/disposal controls prevent disabled V2 from satisfying that absence. Removing the override must turn this pin red.
